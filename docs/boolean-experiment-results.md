# 布尔基因互动域实验（分层生成策略 · 结果文档）

本文档是本分支布尔域实验的唯一结果与数据文档。所有结果来自本地 Qwen2.5-3B-Instruct
Q4_K_M（Ollama 0.40.18，温度 0.7）对官方 HypoSpace 布尔基准（上游提交 `c69e931`）
的真实调用；评测使用官方解析器与 V/U/R 口径。原始调用与响应保存在本地 `runs/`
（按仓库约定不入库），每个数字都可以用 `experiments/` 下的审计脚本从原始记录重放核对。

---

## 1. 任务与方法

### 1.1 任务

官方 **布尔基因互动** 模块（`boolean/`）：两个变量 x（母方基因）、y（父方基因），
运算符 AND / OR / NOT / NOR，表达式嵌套深度 ≤ 2，禁布尔常量。一道题 = 一条观测集
（若干行输入→输出，如 `(x=0, y=1) -> 1`），生成目标 = 与全部观测一致、且在假设空间
内的表达式集合。官方假设空间按机制键去重共 65 个表达式（其中 34 个满足官方深度检查，
见 §6 披露）。官方 V/U/R 口径：

- **V（有效性）**：与观测一致且满足空间约束的表达式占比；
- **U（唯一性）**：空间内不重复表达式的占比（官方 novelty_rate）；
- **R（恢复率）**：按机制键匹配，恢复的兼容表达式占全部兼容表达式（地面真值）的比例。

### 1.2 方法（布尔域分层生成路线，三代）

沿用因果域的「分层生成策略」：只用公开观测 + 空间定义先验分层，不读参考答案、
不做覆盖反馈、不改表示。

1. **补全分层 `completion`（第 1 代）**：观测未覆盖的真值表行逐层补全（每个兼容表达式的
   真值表必是观测的某个补全），口头要求模型生成与补全一致的自由表达式；输出按官方
   解析器原样验收。
2. **单孔骨架 `skeleton`（第 2 代）**：每层再固定一个只带一个槽位 `[?]` 的表达式骨架
   （机制去重、深度 ≤ 2、槽位仅取 x / y / NOT x / NOT y），模型填槽；装配在结构上强制
   整张真值表匹配当层补全，不匹配即丢弃该次尝试。
3. **单孔骨架 + 有效性救援 `skeleton_valid`（第 3 代，最终方法）**：同第 2 代提示；
   装配时若模型填的槽位不满足当层补全（包括输出无法解析的情况），则按固定公开顺序
   确定性救援——保留模型的骨架结构，只修正槽位叶子值。每个调度单元都保证至少一个
   合法实例（由公开空间检查保证），因此 V 逐单元恒为 100%，跨层重复在结构上不可能。

与另两条路线的区别：不读任何已恢复解（分层完全先验）、不改表示（仍输出官方表达式
文本）、不做动作选择或回溯搜索；救援只修正模型自己骨架上的叶子，不引入模型未提议的
结构。实测中模型自填即通过当层补全的调用占 **45.05%**，其余 55% 由救援做最小修正。

### 1.3 配对协议（与基线条件一致）

| 条件 | 取值 |
| --- | --- |
| 测试题 | 12 题（6 题 2 观测 + 6 题 3 观测），官方集合按固定种子抽样（dev 种子 31415 / test 种子 27182，dev 与 test 不重叠，无结果性筛选） |
| 重复种子 | [17, 42] |
| 每题预算 | 16 次调用（四个方法完全相同；13 次调用前缀另报） |
| 模型 / 采样 | 本地 Ollama `qwen2.5:3b-instruct-q4_K_M`（digest `357c53fb…`，Ollama 0.40.18），温度 0.7，采样参数与因果域一致 |
| 评测 | 官方 `boolean_benchmark.py` 的解析与 V/U/R 口径，逐调用重放 |
| 基线 | **官方提示**（上游 `create_prompt` + 历史假设累积，完整官方流程，无任何后处理）；补全分层 `completion` 与单孔骨架 `skeleton` 作为路线内对照 |
| 冻结 | 协议 `experiments/boolean-skeleton.json` 与全部代码在推断前提交（`3895c4a` / `d8dfd97`），运行身份记录在 `runs/boolean-test/identity.json`（源码 SHA + 模型指纹 + 上游提交） |

四个方法之间的**唯一差别是生成过程**（提示面与确定性装配）；题、种子、预算、模型、
采样、评测器完全相同。

## 4. R 的上限与达成度

官方基准的空间枚举把自身公式重新解析后，部分机制键对应的表达式超过深度上限（
「幽灵」条目，官方评测器必拒），但它们的键仍计入地面真值分母，因此 R 存在由官方语义
决定的上限（12 题合计可恢复真值键 75/128，宏观上限 ≈ 57.6%）。最终方法 R=53.69%，
即**达到了官方语义下可恢复上限的 93.2%**；其余 6.8% 的缺口全部来自幽灵键，任何方法
（包括官方提示自身）都无法恢复。

## 7. 可验证性

- **单元测试**：`python3 -m unittest discover -s tests`（64 项，含布尔域 21 项：空间与
  模板枚举、规范化文本往返、补全可行性、计划轮转、三种装配与救援性质、官方评测语义）。
- **逐调用离线审计**：`experiments/analyze_boolean.py` 从 `runs/boolean-{dev,test}/raw`
  重放全部 1,792 通调用（`request_id` + `data_sha256` 校验），独立核对官方提示的历史
  累积与每步提示文本、分层轮转、装配/救援输出与 V/U/R 前缀。
- **运行级重放**：`run_boolean_skeleton.py --split test --replay` 对 96 个单元逐字节
  比对通过（12 题 × 2 种子 × 4 方法）；身份文件冻结模型指纹、上游提交与源码 SHA。
- **披露**：
  1. 官方空间枚举含 31 个「幽灵」表达式（重解析后超过深度上限，官方评测器必拒），其
     机制键计入地面真值 → R 有官方语义上限（§4）；本方法向该上限逼近至 93.2%。
  2. 官方提示模板把操作符集合直接拼接进提示，集合迭代顺序跨进程不定；为保证逐调用
     重放，本仓库固定其排序（仅使提示文本可复现，不改变任何生成条件）。
  3. 有效性救援是确定性的叶子修正：模型骨架自填通过当层补全的调用占 45.05%，其余
     55% 由救援修正；V=100% 是该机制的构造性结果，已在上表逐项披露。
  4. 测试题与开发题按固定种子抽样且不重叠，未依据任何结果筛选或调整采样超参。
- **原始数据位置**：`runs/`（按 .gitignore 约定不入库）；官方基准固定在本地
  `.cache/hypospace`（上游提交 `c69e931`，布尔树清洁）；官方集合生成参数
  `--operators full --max-depth 2 --seed 2026`。
